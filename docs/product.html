Decision Tables as Code

Put business decisions into a small, reviewable data contract: explicit facts in, deterministic rule evaluation, a decision out, and a trace that explains exactly why.

The table is the decision contract. The explainability trace is derived from the same rules, not written after the fact.

Why it exists

Business rules often drift between prose, spreadsheets, code, test cases, and configuration. A decision table gives business and engineering a smaller common surface to review.

01

Keep rules visible

Conditions and outputs stay readable as data instead of disappearing into branching application code.

02

Make precedence explicit

Evaluation order, null handling, and the supported expression subset are deliberate rather than implicit.

03

Explain the result

A trace identifies the facts and matching rule that produced a decision, which makes review and testing practical.

One table, several checks

Validation, linting, policy, execution, explanation, and generated documentation all work against the same source.

Typical loop

dtac validate <table.yaml>
dtac lint <table.yaml>
dtac run <table.yaml> --facts <facts.json>
dtac explain <table.yaml> --facts <facts.json>
dtac doc <table.yaml>

Useful for

Derivations, routing, classification, eligibility, default selection, and other bounded decisions where the business rule matters as much as the output.

Not a general-purpose rule engine. The DSL stays intentionally constrained so decisions remain inspectable and deterministic.

Where it connects

A decision table is often a small part of a larger process, transformation, or change. Keep that relationship visible without bloating the table itself.

Process as Code →Place a governed decision inside a broader operating flow.Mapping as Code →Use explicit decisions alongside deterministic transformation rules.Enterprise Change Graph →Trace a rule change to affected processes, data, and controls.
Agent entry point

A good agent can show its rule.

Agents should validate the table, run only with supplied facts, and return the decision together with the explainability trace. Missing facts are not permission to invent values.

DISCOVER

docs/agent-manifest.json defines supported operations and boundaries.

EVALUATE

Use supplied facts

Facts are inputs; unknown values stay unknown unless the contract defines a default.

EXPLAIN

Return the trace

Always keep the matching rule and reasoning available beside the final decision.
